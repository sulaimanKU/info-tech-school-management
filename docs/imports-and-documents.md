# Private imports and documents

## Import lifecycle

Authenticated users with `imports.manage` upload CSV, XLSX or binary XLS (5 MB maximum, one sheet, 1000 data rows and 50 columns). Formula cells are rejected. XLSX expanded content is capped at 20 MB/2000 archive members. Reader selection is restricted to CSV/XLSX/XLS; arbitrary file type detection is not used. PhpSpreadsheet supplies XML entity protection. UTF-8 text values are limited to 5000 bytes.

`POST /api/v1/imports` returns a private batch ID and headers. `GET /imports/{id}` shows the first ten rows with identity numbers masked. `POST /imports/{id}/preview` accepts a `mapping` object from supported field names to uploaded headers. Mapping accepts only the selected import type's field whitelist. Validation invokes the same controllers/domain rules as individual operations inside a rolled-back transaction. No preview writes persist. Invalid batches report error field names without reproducing submitted personal data. A corrected source can be uploaded again; staging can be removed explicitly.

`POST /imports/{id}/confirm` with `confirm: true` locks and revalidates the batch and imports every row atomically. Any failure rolls back the entire import. Repeating confirmation returns the confirmed report without processing again. Identical uploads are deduplicated per owner/type/content. Repeated source rows are rejected. Batch access is limited to its uploader, even for another administrator. CNIC/contact/source rows are encrypted using Laravel's application key; source rows are cleared on successful confirmation. Staging expires after 24 hours; `school:purge-expired-imports` removes expired source ciphertext. Schedule Laravel's scheduler to run this cleanup.

Types: students, verified guardians (optional student link), staff profiles for existing accounts, classes, opening fee balances, allocated payment history, full-roster daily attendance, full-roster assessment marks, and biometric punch evidence. Staff passwords are deliberately excluded from spreadsheet imports. Create staff accounts through the protected account workflow. Guardian `mobile_verified=1` is an explicit administrator verification assertion, not an SMS-verification claim. Imported marks submit for the existing independent review workflow; they never publish automatically. Existing attendance registers are never overwritten by import.

All IDs in templates are fictional placeholders. Replace them with actual authorized catalog IDs obtained from the API/mobile school setup. Dates must fit the configured session. Amounts are **integer paisa**, not decimal rupees. `payment_history` maps one payment to one existing invoice per source row; use operational payment entry for a payment allocated across several vouchers. Imported bank payments remain pending until authorized verification. Opening balances create immutable invoices and balanced opening ledger entries; repeated periods are protected by financial constraints.

## Biometric evidence

No device vendor assumptions, fingerprints, face vectors or biometric templates are stored. Configure a source/device code and external student ID mapping first. Punch timestamps use `YYYY-MM-DD HH:mm:ss` in Asia/Karachi; direction is `in` or `out`. Unknown IDs and duplicate punches fail validation. All punches are preserved; multiple punches do not silently become additional attendance days. Monthly evidence reports show first/last timestamps, punch counts and missing/conflicting pair flags. Missing punches never imply absence. Review evidence and explicitly submit a complete roster using the attendance register. Hardware-specific adapters can transform vendor files into this documented input without changing the attendance domain.

## Documents

`GET /api/v1/reports/{type}?format=pdf|csv|xlsx` generates authorized data on demand with private/no-store headers. Types: admission, student_id, voucher, receipt, annual_fee, attendance, academic, exam_schedule, salary_slip, financial, registration, communication. Student documents require an authorized `student_id`; vouchers use `invoice_id`, receipts `payment_id`, salary slips `payroll_item_id`. Parent receipts require `student_id` and contain only that child's allocations, even when the original payment covered other children. Only verified receipts and paid salary slips are rendered. Academic reports contain published results only. Financial reports are correctly labelled trial balances, not balance sheets. Annual fee cards use a calendar `year`; attendance uses `month=YYYY-MM`.

PDF uses mPDF, escaped text, supplied official logo and an authorized local student photograph for ID cards. The renderer never accepts arbitrary user HTML, remote image URLs or file paths. CSV protects formula-leading characters; XLSX explicitly types cells as strings. Reports cap at 5000 rows. Exports include identifiers/dates and PKR amounts. Requests are audited without exported values. Android downloads PDFs through authenticated requests and opens app-private temporary copies; those copies are removed when the viewer closes. External viewer access is explicit and disclosed.

Exam schedules have draft/published/cancelled states, optimistic versions, configured-session dates and overlap validation. Only published schedules for a linked child's class appear to parents. Coordinators configure actual schedules; no fictional dates are seeded.
