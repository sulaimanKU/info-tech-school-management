# Production configuration and Android builds

## Required before deployment

Deploy the API over HTTPS with `APP_ENV=production`, `APP_DEBUG=false`, private APP_KEY/CNIC_LOOKUP_KEY backups, PostgreSQL least-privilege runtime credentials and backups/restore drills. Configure trusted proxies and stable shared rate-limit/session cache for multiple API workers. Run reviewed additive migrations, then `php artisan school:seed-mobile`. Do not run validation database commands on a live database. Confirm session/calendar dates and all fee/discount/payroll settings with school management before admitting operational records. No children/demo records are automatically seeded by the normal application seeders.

Serve only `api/public`; keep `storage/app/private`, uploaded documents, PDF temporary files, environment files, signing keys and service-account JSON outside unrestricted public access. Persistent shared storage/volume and backups are required across deployments. Current private file implementation uses Laravel's local disk; a production object-store adapter must preserve authorization/private streaming, never public student URLs. Add the school's malware scanning/retention requirements before allowing untrusted document sources at scale. Run `php artisan schedule:run` every minute for announcement/push dispatch and expired import cleanup. Monitor delivery failure counts, storage, database backups and server error metadata without collecting request bodies/secrets.

The school must approve the operational privacy/terms text, official support contacts, retention schedule and any required legal disclosures before distribution. The app truthfully identifies that review requirement; it does not invent phone numbers, legal approval or a retention period.

## SMS and CNIC/OTP

`SMS_DRIVER=disabled` is the safe default. Parent request is uniformly unavailable until a provider is configured; staff login remains independent. `SMS_DRIVER=local` works only with local/testing environments. It generates cryptographically random six-digit OTPs, stores only hashes in PostgreSQL, keeps delivery encrypted in a private short-lived local cache and exposes a one-use **interactive CLI** `school:local-otp {challenge}`. There is no OTP-returning HTTP endpoint and OTP values are never application log fields. The optional emulator injector additionally requires the exact isolated test database and enters the local delivery directly through ADB without printing it.

Challenges expire after five minutes, have five attempts, one-minute resend cooldown and network throttles. Failed attempts are committed, replay is denied and responses do not reveal guardian existence or mobile numbers. Real SMS requires a Pakistani-compatible gateway account, sender/template approval and a new SmsProvider implementation wired in AppServiceProvider. Do not use the local simulator in production; provider selection makes that impossible. A production adapter should enqueue delivery privately to avoid introducing lookup timing differences, report gateway failures safely and never log gateway payloads/codes.

## FCM

Backend `PUSH_DRIVER=disabled` keeps in-app history operational without claiming delivery. To enable real delivery, set `PUSH_DRIVER=fcm` and `FIREBASE_CREDENTIALS` to a private Google service-account JSON absolute path; enable FCM HTTP v1 and grant only required messaging permissions. The adapter uses RS256 service-account OAuth with encrypted cached access tokens, a fixed Google token endpoint and fixed FCM host. Tokens are encrypted in the database and bound to an authenticated session. Suspension/logout/expiry prevents delivery. The dispatcher uses leased delivery rows, capped attempts/backoff, deduplicated notification/device pairs and invalid-token revocation. FCM success means provider acceptance, not proof the device displayed it. Delivery is at-least-once; Android notification tags reduce duplicate tray entries.

Android is opt-in. Supply your registered `com.infoteach.school` Firebase project's values with `--dart-define=FCM_ENABLED=true`, `FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_SENDER_ID`, `FIREBASE_PROJECT_ID`. These mobile project identifiers are not the private service account key. Keep the private JSON out of the app/Git. Options are initialized explicitly; no fabricated google-services.json is included. Account support/settings offers Android permission enrollment/disable; denial leaves in-app history available. Alerts contain only generic school text and a notification-history identifier, never names/CNIC/marks/amounts. Tapping opens authenticated history, then the authorized record. Real Firebase delivery has not been claimed without credentials/device testing.

Official setup references: [FCM Flutter](https://firebase.google.com/docs/cloud-messaging/flutter/get-started), [HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).

## WhatsApp and biometric hardware

WhatsAppProvider is an optional unavailable provider interface only. No messages are sent and core operations never depend on it. Actual business account, templates, consent and credentials would require a later adapter. Biometric hardware specifications are not assumed; use configured ID mapping and validated CSV/XLSX/XLS punch evidence. Verify the actual machine's timezone, IDs, direction semantics and export format before preparing an adapter. No fingerprints/templates are stored.

## Android

Flutter assets are the original `assets/1.jpeg`/`2.jpeg`. Launcher/splash derivatives are reproducible with `php -d extension=gd tool/build_branding.php` from mobile. Android requires INTERNET; POST_NOTIFICATIONS is optional and requested only when enabling configured notifications. No broad storage, contacts, camera or biometric-template permission is requested. Secure storage, disabled Android backup, RTL and keyboard resize are configured. Release API configuration rejects non-HTTPS URLs. Debug allows the emulator's host API address.

Run from mobile: `dart format .`, `flutter analyze`, `flutter test`, then `flutter build apk --debug --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1`. The resulting APK is `build/app/outputs/flutter-apk/app-debug.apk`. The debug URL is development-only, not a production server. Windows cross-drive pub-cache builds use `kotlin.incremental=false` and in-process compilation to avoid invalid Kotlin cache roots. Firebase's current plugin emits a future built-in-Kotlin migration warning; builds must be revalidated when updating Flutter/plugins.

Copy `android/key.properties.example` to ignored `android/key.properties` and supply your private upload keystore/passwords locally or in CI secrets. No signing key/password is generated or committed. Release configuration uses that key only if present and never substitutes the debug key. Production builds: `flutter build apk --release --dart-define=API_BASE_URL=https://YOUR_APPROVED_API/api/v1` and `flutter build appbundle --release` with the same API define and optional Firebase defines. Unsigned validation artifacts are not Play Store-ready. Choose/secure Play App Signing/upload-key ownership, confirm app ID, version code, privacy/data-safety declarations and school policy before distribution.
